# 仓库约定

这个仓库是主题源码，不是某个人站点的备份。下面写清楚什么该进、什么不该进、什么是默认值。

---

## 该提交的

主题装上就能跑的东西：

```
*.php                 模板与入口
src/                  主题逻辑
views/                模板片段
assets/               样式、脚本、字体、图标、默认图
extras/               站点根用的附加脚本（sitemap、在线统计）
tools/                发版与检查脚本，不进主题运行时
docs/                 使用文档与示意截图
package.json          npm 包声明，只含 assets/
.npmignore
README.md
CHANGELOG.md
LICENSE
screenshot.png        仓库首页展示图
.gitignore
```

判断标准：**换一台干净的 Typecho，只放这些文件能不能正常显示**。能，就留下。

---

## 不该提交的

| 类型 | 例子 | 原因 |
|---|---|---|
| 个人配置值 | 站点域名、邮箱、备案号、二维码、赞赏码、统计 ID | 别人装了会显示你的信息 |
| 密钥与令牌 | API token、推送密钥、面板口令 | 泄露即失守 |
| 数据库 | `*.sqlite`、`*.sql` 导出 | 含真实内容与评论 |
| 上传附件 | `usr/uploads/` | 体积大，与主题无关 |
| 缓存与临时文件 | 缓存目录、`*.log`、`tmp/` | 每次运行都会变 |
| 打包产物 | `*.zip`、`*.tar.gz` | 应由 Releases 提供 |
| 备份文件 | `*.bak`、`*.orig`、`sidebar-old.css.bak` | 没人引用，还会被 npm 包一起带走 |
| 编辑器与系统文件 | `.idea/`、`.vscode/`、`.DS_Store` | 个人环境相关 |

`.gitignore` 里已经拦住大部分，但**提交前还是要看一眼 `git status`**。

## 默认值规范

主题设置里的每一项，默认值都必须是「对陌生人无害」的：

```php
'qq_icp_number'   => ['text', 'ICP 备案号', '', '页脚展示并链接到工信部', [], 'basic'],
//                                        ↑ 空字符串
```

| 字段类型 | 默认 |
|---|---|
| 文本类（标题、描述、备案、邮箱） | 空 |
| 图片地址（头像、封面、二维码、赞赏码） | 空；留空时回落到主题自带图或直接不显示 |
| 开关类 | 关闭或最小影响 |
| 统计与推送（百度 token、Clarity ID） | 空 |
| 版权与署名 | 保留作者署名，这是主题的一部分 |

留空的项在使用时自动隐藏，不会输出空标签。

---

## 命名与路径

- 主题目录固定 `qiqi77`，配置存在 `theme:qiqi77` 这个键下，改名会丢配置
- 所有站内地址用相对路径，**不要写死域名**；装在哪一层目录都能跑
- 图片、字体放 `assets/`，不要放站点根

---

## 版本与发布

1. 改代码
2. 本地跑一遍：首页、文章、分类、搜索、404、评论提交
3. 确认没有个人数据：`grep` 域名、邮箱、token
4. 更新 `CHANGELOG.md`
5. 打 tag：`v1.0.0`
6. 发 Release，附 zip

版本号遵循 `主.次.修订`：

- 主：破坏性改动（改配置键名、改目录结构）
- 次：新增功能
- 修订：修 bug

## 提交前自查

```bash
# 有没有个人域名/邮箱/token 混进来
grep -rn "你的域名\|你的邮箱\|ghp_\|token" --include=*.php --include=*.md .

# 有没有把数据库带进来
git status --short | grep -E "\.sqlite|\.sql|\.zip"

# 默认值是不是都空着
grep -n "=> \['text'" src/Options.php | head
```

三项都干净，再提交。
